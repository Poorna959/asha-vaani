# Android Release & Integration Contract (`asha-vaani-web`)

This document specifies how the future completed Android application (`com.ashavaani.app`) integrates with this web application for:
1. **Zero-code APK publication** from the Android Gradle build output.
2. **Release Manifest API (`GET /release.json`)** for web downloads and optional in-app update checks on Android.
3. **Backend Orchestrator Compatibility** with the existing FastAPI service in `/home/poornachandra-s/Desktop/poorna/backend`.

---

## 1. Publishing the Completed Android APK (1 Command)

Until you publish an APK, `public/release.json` has `"latest": null` and the website displays **"Coming Soon — In Final Build Verification"**.

When your Android APK is ready:

### Option A — Publish a signed release APK (Recommended for production)
```bash
# 1. Build the signed release APK in ../android:
cd /home/poornachandra-s/Desktop/poorna/android
./gradlew :app:assembleRelease

# 2. Publish it to the web application in ../web:
cd /home/poornachandra-s/Desktop/poorna/web
npm run release -- ../android/app/build/outputs/apk/release/app-release.apk \
  --notes "Signed release with Gnani Prisma v3.0 & Timbre v3.0" \
  --notes "Room v2 offline outbox and 12-item NHM danger-sign firewall"

# 3. Rebuild the static bundle for deployment:
npm run build
```

### Option B — Publish a debug APK for internal / hackathon judge testing
By default, `npm run release` blocks debug-signed builds so a debug APK is never published accidentally. Pass `--allow-debug` when distributing an internal test build:
```bash
cd /home/poornachandra-s/Desktop/poorna/web
npm run release -- ../android/app/build/outputs/apk/debug/app-debug.apk \
  --allow-debug \
  --force \
  --notes "Hackathon judge test build (v0.3.0)"
npm run build
```

### What `npm run release` does deterministically
1. Verifies the file extension (`.apk`) and ZIP magic header (`50 4B 03 04`).
2. Reads `output-metadata.json` generated by the Android Gradle Plugin alongside the APK to extract `applicationId`, `variantName`, `versionName`, and `versionCode` (or accepts `--version-name` and `--version-code` overrides).
3. Verifies `applicationId === "com.ashavaani.app"` and ensures `versionCode` strictly increases (unless `--force` is passed).
4. Computes exact byte size and lowercase hex **SHA-256** digest.
5. Copies the APK to `public/downloads/asha-vaani-v<versionName>.apk` and verifies the copied file's SHA-256 digest.
6. Atomically writes `public/release.json`, moving any previous `latest` release into `history` (sorted newest first).

## 2. Release Manifest Contract (`GET /release.json`)

Both the web application (`src/lib/release.ts`) and any future Android in-app update checker consume `/release.json` (`Cache-Control: no-cache, no-store, must-revalidate`).

### Schema (`schemaVersion: 1`)

#### Coming-Soon State (before first APK publication)
```json
{
  "schemaVersion": 1,
  "app": {
    "name": "ASHA Vaani",
    "packageName": "com.ashavaani.app",
    "minSdk": 26,
    "minAndroidVersion": "8.0"
  },
  "latest": null,
  "history": []
}
```

#### Published State (after running `npm run release`)
```json
{
  "schemaVersion": 1,
  "app": {
    "name": "ASHA Vaani",
    "packageName": "com.ashavaani.app",
    "minSdk": 26,
    "minAndroidVersion": "8.0"
  },
  "latest": {
    "versionName": "1.0.0",
    "versionCode": 2,
    "releasedAt": "2026-11-22T00:00:00.000Z",
    "file": "downloads/asha-vaani-v1.0.0.apk",
    "sizeBytes": 18218373,
    "sha256": "978ee6fa78baefd61049db549bbae0d54781a863681195b1b0a9796e80b4e6e9",
    "notes": [
      "Signed production APK with Prisma v3.0 & Timbre v3.0",
      "Room v2 offline outbox"
    ]
  },
  "history": [
    {
      "versionName": "0.2.0",
      "versionCode": 1,
      "releasedAt": "2026-11-21T00:00:00.000Z",
      "file": "downloads/asha-vaani-v0.2.0.apk",
      "sizeBytes": 18218373,
      "sha256": "978ee6fa78baefd61049db549bbae0d54781a863681195b1b0a9796e80b4e6e9",
      "notes": ["Internal preview"]
    }
  ]
}
```

### Field Validation Rules
| Field | Type | Rule |
| :--- | :--- | :--- |
| `schemaVersion` | `1` | Fixed integer version (`1`). |
| `app.packageName` | `string` | Must match `com.ashavaani.app`. |
| `app.minSdk` | `integer` | Positive integer (`26` = Android 8.0 Oreo). |
| `latest` | `Release \| null` | `null` when coming soon, or a valid `Release` object. |
| `latest.versionName` | `string` | Semantic version (`^\d+\.\d+\.\d+(?:[-+][0-9A-Za-z.-]+)?$`). |
| `latest.versionCode` | `integer` | Positive integer matching Android `versionCode`. |
| `latest.releasedAt` | `string` | ISO-8601 UTC timestamp. |
| `latest.file` | `string` | Relative path matching `^downloads/[A-Za-z0-9._+-]+\.apk$` (prevents path traversal or external URL injection). |
| `latest.sizeBytes` | `integer` | Exact file size in bytes (`> 0`). |
| `latest.sha256` | `string` | 64-character lowercase hex SHA-256 digest. |
| `latest.notes` | `string[]` | Human-readable release notes. |

## 3. Optional In-App Update Check from Android (Kotlin + OkHttp)

When the Android app is ready, it can check `<WEB_APP_ORIGIN>/release.json` to notify the ASHA worker or PHC supervisor when a newer APK is published:

```kotlin
@Serializable
data class WebReleaseManifest(
    val schemaVersion: Int,
    val latest: WebReleaseEntry? = null,
)

@Serializable
data class WebReleaseEntry(
    val versionName: String,
    val versionCode: Int,
    val file: String,
    val sizeBytes: Long,
    val sha256: String,
    val notes: List<String> = emptyList(),
)
```

Compare `manifest.latest != null && manifest.latest.versionCode > BuildConfig.VERSION_CODE`, and if true, open `<WEB_APP_ORIGIN>/download` or download `<WEB_APP_ORIGIN>/${manifest.latest.file}` and verify its SHA-256 digest before prompting the package installer.

## 4. Existing FastAPI Backend Endpoints Used by the Android App

Because the `poorna` repository was left completely untouched, all existing FastAPI endpoints remain 100% compatible with the Android client:

- `WS /ws/session` — Full-duplex 16 kHz mono PCM voice session (`session_start`, `language_change`, `barge_in`, `register_select`, `patient_select`, `reset_session`).
- `GET /health` — Active Gnani (`prisma-v3.0`, `timbre-v3.0`) and LLM provider status.
- `GET /api/visits` & `GET /api/visits/{id}` & `PATCH /api/visits/{id}/acknowledge` — Structured visits & PHC acknowledgement.
- `GET /api/follow-ups` & `PATCH /api/follow-ups/{id}` — Follow-up queue management.
- `GET /api/danger-signs` — Canonical 12-item NHM danger-sign catalog (`v1.1`).
- `GET /api/registers`, `POST /api/registers`, `GET /api/registers/{id}/patients?q=`, `POST /api/registers/{id}/patients`, `GET /api/patients/{id}/profile`, `PATCH /api/patients/{id}`, `GET /api/patients/{id}/followup-context`, `GET /api/registers/{id}/export?format=xlsx|csv`.
